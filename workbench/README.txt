ABD-FOC · AI-Based Development for Field-Oriented Control

模块化的关节模组开发工作台。使用单一当前配置，货架和测试记录由控制台共享。架构页用于查看模块职责和数据关系，具体配置在“工程”中完成。

启动
需要 Node.js 22 或更新版本，不需要安装 npm 依赖。
在仓库根目录运行 npm start，再打开 http://127.0.0.1:4317/。
macOS 也可双击仓库根目录的「启动工作台.command」。
如果端口被占用，可运行 ACTUATOR_PORT=4318 npm start。

工程
配置文件的导入、保存、导出和预置入口集中在“工程”，按以下六步进行：
1. 选型：选择电机与减速机组成的执行器，可独立保存，无需先创建关节模组。
2. 硬件：按内核 → 外设 → 驱动 → 保护配置，也可复用货架驱动器。
3. 算法：配置算法管理、反馈解算、电流环、变换与调制，按需启用状态观测和摩擦补偿；电流环内配置保护，各模块维护自己的参数和数据结构。
4. 应用：配置调度、参数存储、通信解析、运动控制、校准和故障处理。错误码在保护与诊断模块中配置，协议与解析在通信协议模块中配置。
5. 构建：设置编译器、全局和模块优化选项；点击构建时检查当前选型、模块参数、数据结构与实现支持，通过后生成、编译。
6. 烧录：选择对应当前配置的已构建固件和 J-Link 探针，显式写入并校验双核镜像。
配置目录采用树形导航，硬件、算法、应用层分别展开子模块。每一级独立使用 01、02 等序号，通过缩进与连接线表示归属；内核、外设、驱动、保护四个模块均可独立折叠；模块下提供参数配置与数据结构入口。折叠偏好保存在当前浏览器标签页，切换模块时只展开目标路径，刷新保留其他分支状态。点击子模块后仅显示当前编辑内容，并可按“上一个模块 / 下一个模块”依次配置。参数、数据结构和依赖检查通过后自动打勾，修改后立即重新检查；未编译的可选模块单独标记。对勾不代表设备实测通过，完整固件的实现支持在构建时自动检查。当前仅配置单电机，不提供电机数量或手动相序映射参数。
每次生成或构建都会检查所提交的最新配置，不需要先单独执行检查。前端与本地服务均执行校验；失败通过通知汇总并提供修改入口，检查期间修改配置会中止提交。

货架
执行器 = 电机 + 减速机；关节模组 = 执行器 + 驱动器。
在组装区拖入两类组件，命名并保存为关节模组，也可点击组件右侧的 ＋。只有两类组件均有效的组合才计入关节模组数量；未完成搭配独立显示。
组件可在多个模组中复用。保存关节模组与选为当前配置是两个独立操作；配置引导中的执行器、驱动器选型不会自动创建货架组合。
驱动器保存 MCU / PCB 信息、四个硬件模块的参数，以及外设和引脚分配。
复用驱动器带入整套硬件配置；显式保存时才将调整后的配置存回货架驱动器。
硬件按四组配置，不再显示重复的横向快捷入口：
- 内核：共享晶振与总线时钟；hw-platform.coreConfigs 分核保存频率、时基、中断、缓存与浮点约定。H745 的 M4 频率需等于 D2 HCLK，不显示不存在的缓存开关。模块分工与核间协作沿用 execution，RAM / FLASH 沿用部署配置。
- 外设：hw-board.resources 保存外设实例、信号引脚及参数；由已维护的完整 MCU / 封装映射限制选择，目前提供 STM32H745IIK6 的部分已核对路由。
- 驱动：电机侧编码器、出轴侧编码器、力矩传感器引用外设资源。通信方式、外设参数及帧格式可在驱动卡片中配置；通信参数直接写回同一外设资源，共用总线时同步生效。通信分为请求应答和主动上传两种模式；前者按请求发送，后者仅初始化时发送启动命令，随后只接收，数据超时不会重发启动命令。设备上电即上传时，启动命令可留空。帧格式包括帧头、帧尾、长度、数据偏移、数值类型 / 位宽 / 字节序、倍率 / 偏移、状态掩码及校验。配置随驱动器、导出文件和层版本保存。
- 保护：hw-safety.tripPaths 保存故障输入、关断目标、刹车或中断路径、有效电平、优先级及滤波；锁存关断由应用授权复位。常规轮询保护归应用层。
PCBA 资源及保护路径随驱动器、配置导入导出和硬件层版本快照保存。引脚冲突、接口类型及失效引用均参与依赖检查。
驱动解析只依赖通信与帧参数，不按厂商或型号选择实现。NEO 的 GW、KW、LD、SMH 仅作为协议参数预置，XH 未确认字段保留待配置。通用接收解析已实现；真实外设收发、定时触发及硬件关断路径仍需平台适配，不能由配置页面的选中状态推断已经接通。

复用时保留算法与应用配置；选型会按已知组件电流边界收紧现有电流限值。

测试记录
测试页记录关节模组的 Kt（电流—力矩）与 TN（转速—力矩）实测表格和曲线。先选择已搭配完整的关节模组，再手动填写测量点，或粘贴 CSV 导入。
按实际测量选择电机侧或关节输出侧；Kt 另选 Iq 电流或相电流有效值。转速、力矩与电流口径不自动换算，曲线按各组原始记录顺序连线，不拟合单一 Kt 或推断连续额定力矩。
保存记录会同时保存原始测量点、工况、实测固件标识，以及当时的执行器、驱动器、三层版本与构建配置快照。记录关联到关节模组，在货架详情可回看。实测记录保存在控制台本地数据中，导入配置不会替换这些历史，配置文件导出不包含全局实测记录。
Kt 与 TN、不同关节模组各自保留当前会话的录入草稿。填写后点击“保存记录”提交到货架历史；保存配置不能代替提交测量记录。
当前支持数据录入与整理，没有自动控制硬件或采集测试数据。

型号选项
MCU 型号、板卡、编码器与力矩传感器型号使用统一下拉框，只列维护的内置选项。新增型号需在代码中完成模型、资源和固件适配后加入目录，不提供手动编辑选项入口。配置中未适配的已有型号保留显示，不自动加入可选列表。实际生成支持仍由构建检查确认。
MCU 能力选项统一维护在 modules/hardware/hw-platform/options.mjs。目前 STM32H745 的 ADC 分辨率、ADC 采样周期、中断优先级及 SPI 字长按芯片 / 外设提供选项；SPI2 支持 4–32 bit，SPI5 支持 4–16 bit。ADC 触发源只列已维护的来源。货架和项目编辑器复用同一选项与校验，非法导入值也会阻止检查通过。未维护的 MCU 不套用 H745 能力表。电压、增益与目标时钟等连续参数仍使用数值输入。
下拉菜单只包含真实选项；空值显示为“—”，不会自动选中硬件。“支持 / 不支持”等二选一配置可直接点选。

RAM
在硬件层的内核模块中打开“部署配置”，统一规划执行内核、Flash 和 RAM。
RAM 使用通用区域名称和能力声明：起始地址、容量、可访问内核、代码执行与 DMA 访问。芯片专用名称仅作为区域标签。
STM32H745 可载入物理内存区域表；这不是固件空闲内存表。按代码、数据、栈、堆、共享数据和 DMA 缓冲区填写运行位置与容量预算。
代码与初始化数据可分别选择 Flash 加载源和 RAM 运行区域。检查覆盖地址重叠、越界、容量、内核访问、执行能力、DMA 访问与跨核共享区冲突。
RAM 配置随配置 JSON 保存。新生成器尚未实现链接脚本、启动复制表和硬件装配，构建检查会阻止输出可烧录镜像；选择预置布局也不绕过这一条件。

功能与数据
架构页以应用、算法、硬件三层展示十六个子功能，可逐层查看职责、输入、输出、状态与依赖。架构展示只读，不随当前配置的模块开关隐藏功能，也不提供参数编辑入口。
每个功能固定一份输入、输出、状态结构，共 48 份模块结构。模块默认结构包含实际实现使用的字段，直接生成对应的 C 类型；字段名、类型、长度或单位改变后，必须同步修改模块实现才能通过生成检查。在工程的对应模块内编辑字段、名称和参数；模块状态不可直接作为跨模块接口端点或协议载荷。
每个模块提供“配置 / 数据 / 接口”三个页签。接口页仅显示与当前模块相关的连接，新增输入或输出接口时自动绑定当前端点，之后选择对端模块并配置版本、更新时序、交接方式及逐字段映射。配置树只保存手动展开/收起的状态，自动定位仅展开当前路径，不把浏览过的节点累积为常开分支。
检查覆盖缺失/重复映射、字段类型、数组长度、单位及端点归属；切换接口模块会清空原映射。
架构页的层间连线说明数据交换关系；实际数据连接、结构与版本组合在工程内编辑。普通模块由统一执行入口消费输入、更新状态并发布输出，无需在控制台逐个定义函数签名。
三层图形使用初始化一次的亮度网格绘制。右上角设置弹层提供浅色、深色、跟随系统三种主题，以及动效开关；偏好保存在当前浏览器。动效开关独立于设备运行，系统偏好减少动态效果时默认暂停。
工程的模块卡片统一使用“必需”“编译”“运行”三种标签。必需模块只显示“必需”，固定参与编译并启用运行；可选模块提供“编译”和“运行”两个开关，编译期排除后运行期不能启用。运行标签表示配置许可，不是设备实时状态。
字段说明收进问号提示，支持鼠标悬停、键盘聚焦、点击固定和 Esc 关闭；输入合法性错误保留在字段旁。
十进制数字输入框在非编辑状态显示千位逗号，聚焦后以原始数字编辑，失焦后恢复分组。支持负数、小数、科学计数法和规范的逗号粘贴；不截断小数位，保存和导出仍是 JSON 数值。格式、范围和步长错误显示在输入控件处。地址、版本号与协议字节等文本字段保持其原有格式。鼠标滚轮和触控板滚动不会改值；方向键仍按步长调整。
电机极对数只在当前执行器的电机参数中配置；算法层读取当前选中的执行器，电流环也使用同一来源的电阻、电感与带宽计算内部增益。
构建步骤统一配置编译器、工具链版本、全局优化和 LTO，并设置各模块的优化等级；未单独设置的模块继承全局。其他模块配置不重复设置优化等级。
烧录位于工程的最后一步。调试页面独立管理调试连接、变量、波形与日志入口。运行页面记录 CAN FD / EtherCAT / Ethernet 的连接和关节输出侧给定。
界面使用细描边、卡片底板和 Canvas 线场。执行器使用青绿色标识，驱动器使用蓝色标识；关节模组同时包含两类标识。
传感器驱动按电机侧编码器、出轴侧编码器、力矩传感器分组；霍尔是编码器类型。
编码器厂商、型号、通信接口、资源、角度语义与更新有效期独立配置。线性霍尔使用 sin/cos 通道。
MCU 型号通过维护的器件目录自动识别架构；未知型号显示待识别，不开放手动架构选择。
硬件层、算法层、应用层可分别保存配置快照并组合。版本号是任意非空文本，接口标识按声明精确匹配。
快照包含本层模块配置与开关，硬件层另含目标硬件；共享数据结构、协议、货架和构建设置不随快照切换。
版本声明匹配不代表运行兼容。所选版本声明参与固件配置指纹，未选历史版本、运行页草稿和实测记录不影响该指纹。货架中与当前选型无关的资产修改也不使当前构建过期。
依赖检查涵盖模块关系、数据引用、故障动作、协议载荷、组件约束、引脚重复与存储容量。

固件加密
构建步骤的“固件加密”独立于编译器和优化配置，默认关闭，随配置保存并参与配置指纹。关闭时沿用本地开发、编译与 J-Link 调试流程。
服务器签名加密服务和设备 Bootloader 尚未接入。开启加密后，本地生成与编译会明确拒绝，不会回退输出明文固件；现有 J-Link 烧录通道不接收加密包。
build-service/ 将服务端策略接入独立构建入口：生产环境和使用者交付必须加密，开发环境的开发者可选。身份与环境来自服务端，不相信配置 JSON 中的角色。加密交付尚未接入；详细接口与部署边界见同目录 remote-build.txt。

保存范围
当前配置、共享货架与已提交的性能记录自动保存在当前浏览器，整体没有项目列表或项目切换。使用 localStorage 持久化；清理网站数据后不保留，未提交的测量表需先保存为记录。
从工程导入 JSON 时，只替换控制配置并合并文件携带的资产，保留当前控制台身份、已有货架和性能历史。相同 ID、相同内容的资产直接复用；相同 ID、不同内容则创建副本，并重映射执行器、驱动器、关节模组及当前选型的引用。重复导入同一文件不会反复追加相同副本。
配置导出仅包含当前控制设置和选型所需的执行器、驱动器、关节模组；未选资产及全局性能历史不随文件导出。该文件可在配置入口重新导入，用于复用当前控制方案，不能代替完整货架与历史数据备份。
货架 JSON 的 actuators 字段对应执行器，assemblies 对应关节模组；activeActuatorId 可独立保存执行器选型，activeDriverId 为空表示自行配置硬件。
未知数值使用 null；预置参数不代表硬件已验证。组件变更不会静默覆盖已应用的控制参数。

JSON 构建接口
“检查并构建”先进行客户端校验，再将配置 JSON 直接 POST 到 /api/v1/build；服务端独立检查、生成、编译，成功返回一个 HEX 文件，失败返回能定位模块/参数的 JSON 诊断，不需要预先请求检查接口。
独立构建服务为 build-server.mjs（npm run start:build-service），只提供 POST /v1/build，不提供源码、ELF/MAP、日志或设备接口；它与网页使用相同的构建处理实现。启动凭据、明文开发权限、响应格式见 remote-build.txt。
关闭加密时合并各核镜像为一个带地址的 Intel HEX，不填充镜像间的空隙；响应头含配置指纹、格式标识和文件 SHA-256。三层版本和每核镜像的元数据保存在服务端。网页校验响应后提供“下载 HEX”；配置发生变化时不会应用旧响应。下载结果仅在本次页面会话保留；本机开发的构建记录与原始产物另行保存。
完整固件适配尚未完成时接口会拒绝交付，不会把模块静态库或占位字节作为固件。接口成功路径使用测试后端验证；当前真实 NEO 配置仍返回目标适配问题，未完成远端部署或实机烧录。

当前范围
支持配置设计、产品组合、参数与依赖检查、通知历史和性能记录。
生成器已改为 native/generator 下的新模块实现，不读取或复制 neofsa 工程，不使用原 mc 运行上下文。参考项目只提供预置参数和器件帧信息。
代码直接按模块命名，例如 CurrentInput / CurrentOutput / CurrentState 与 current_step()，不添加统一的产品名前缀。载入已保存工程时会清理旧自动结构名上的 Abd/Adb 前缀，保留字段、结构 ID 和接口引用；自定义结构名保留。每个已编译模块在 firmware/hardware、algorithm、application 下生成独立的一对 .c/.h；编译期排除不输出文件，运行期关闭保留代码和默认运行标志。
已实现的可移植部分包括通用帧收发状态、数据重组与校验、采样快照、保护锁存、编码器反馈解算、带宽电流环、坐标变换与调制、反馈 PLL、库仑/粘性摩擦补偿、电流给定仲裁、命令有效期、周期任务释放、记录提交和静止标零。
每份生成目录位于 .workbench-local/generated/<id>/，包含 project.json、module-contracts.json、build-manifest.json 和 tools/compile.py。可用 GNU Arm GCC 将模块编译成 CM7 / CM4 静态库；编译按核选择 CPU、FPU、浮点 ABI，按模块应用优化等级，支持 LTO，指定版本时核对已安装编译器版本。
模块库明确标为 artifactKind=module-library、firmwareReady=false，不生成 BIN / HEX，不允许连接或烧录。旧生成器记录保留为历史，不作为新架构固件使用。
完整固件尚缺 MCU 启动、时钟、中断、ADC/PWM/串行外设、硬件故障关断、模块交接、双核 IPC、Flash 端口和通信协议栈。CiA 402、速度/位置/PD/力矩外环、运动校准与摩擦辨识的新实现也尚未接入。选中这些功能会明确阻止对应源码生成或完整固件构建，不复用旧实现补齐。
NEO 预置保留需求中的 CiA 402、EtherCAT 分工和校准选项，因此现在导入后会显示上述实现缺口，不能直接生成可运行固件。未知的传感器有效期、量程等仍需按实际设备确认。
存储配置保持校准、参数、日志各一个扇区；电角度零位归校准，出轴标零、力矩标零归参数。这些部署规划尚未接入新固件的 Flash 读写。
J-Link 本地桥和波形页面保留，但新的设备采样 ABI、构建身份及真实采集尚未装配到新固件。此轮未连接、烧录或运行物理设备。运行页面的总线控制、独立分层 OTA 和多轴资源分配尚未实现。

新增或修改某个控制模块，先读 web/src/modules/README.txt。
新增页面把模型、视图和页面交互放到 web/src/features/<功能>/，公共交互放到 web/src/shared/；避免业务逻辑继续堆入 app.mjs。
本地生成的代码、工具链和构建历史在仓库根目录 .workbench-local/，不混入网页源文件。

工具链
本地服务默认寻找 .workbench-local/toolchains/arm-gnu-expanded/Payload/bin/arm-none-eabi-。
可用 ACTUATOR_GCC_PREFIX 指定其他 GNU Arm 工具链前缀；不需要原驱动工程路径。
本机工具使用 GNU Arm 15.3.Rel2、Python 3.14 与 SEGGER J-Link V9.92。
启动后的网页只连接 127.0.0.1，不会上传工程。构建记录保存在 .workbench-local/build-jobs.json。
控制台数据保存在各端口自己的 localStorage；重启服务保留本地配置、货架、测试记录与构建目录。

型号命名
规范格式：系列_尺寸代号_减速机类型_编码器名称_力矩传感器名称。
例如 NEO_75_H_GW_KW：NEO 系列、75 尺寸代号、H 谐波减速机、GW 编码器、KW 力矩传感器；E 代表行星减速机。
尺寸代号不自动推断为毫米。名称解析不代表该组合已经完成固件适配。
配置、货架型号和构建清单统一采用规范名称，不保留旧型号别名或迁移逻辑。参考参数已整理到预置文件中，运行时不读取原工程。

设置中的“导出全部数据”保存完整货架、当前配置和已保存的测试记录。工程中的“导出配置”只输出当前选型所需的配置文件。
